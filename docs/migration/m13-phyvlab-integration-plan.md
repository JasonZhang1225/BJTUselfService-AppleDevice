# M13：物理在线（phyvlab.bjtu.edu.cn）接入目标文档

> 状态：规划中（2026-08-09 立项，**调研先行**）。范围与验收以本文档为准；实施计划另附。
> 上游需求来源：用户 2026-08-09 提出「接入物理在线平台」，并指出该平台「应该借助了某个通用框架」「应该可以复用 MIS 系统认证」。

## 1. 背景与现状

- 平台：`https://phyvlab.bjtu.edu.cn/?redirect=0`（北京交通大学物理虚拟实验/物理在线平台）。
- 公开检索确认该域名为学校物理实验相关站点（曾作为北京市大学生物理实验竞赛官网 `phyvlab.bjtu.edu.cn/bjwlsyjs/`）。
- 用户判断平台基于某个**通用实验平台框架**，且**可复用 MIS 认证**——这与智慧教学平台（M5-4/M5-5）经 MIS module 28 SSO 的模式一致，可信度高。
- **关键约束**：用户当前无法连接校园内网，目标站打不开，无法做内网调研。

### 已验证的外网可达性（2026-08-09）

| 检查项 | 结果 |
|---|---|
| DNS | 解析正常 |
| TCP 443 | **不通（超时/无响应）**——外网被拦，站点为内网资源 |
| 公开检索 | 确认域名归属学校物理实验平台 |

> 结论：**任何真实握手、Cookie、页面结构、登录流程验证，都必须在内网或 VPN 环境下进行**。当前只能做离线设计与调研计划。

## 2. 目标

把物理在线平台的核心只读能力接入 App，让用户在移动端/桌面端查看物理实验相关信息，并按平台习惯安全地进入网页流程：

- 复用 MIS 会话完成平台 SSO，拿到平台可用身份。
- 解析平台核心数据（实验列表/预约/成绩/通知等，以真实页面为准），缓存并展示。
- 需要复杂网页交互（仿真、提交、报告）时，用平台网页容器承接，不硬搬全部网页功能到原生。

## 3. 范围

### 包含（分两阶段）

**阶段 1：调研（必须在内网/VPN 完成）**

- 记录平台登录链路：从 MIS 哪个 module / 哪个 SSO 入口跳转，经过几跳 302 / 表单 POST，最终落地 URL 与 Cookie 名。
- 判断平台框架归属（页脚/版权/静态资源路径/接口命名），确认是否为已知通用实验平台。
- 盘点可安全只读的接口与页面，区分「可原生解析」与「必须 WebView」。
- 形成逐页功能清单与脱敏视觉基线。

**阶段 2：实现（以调研结果定范围）**

- 共享层：SSO 握手（复用 `followSmartHandshakeRedirects` 逐跳白名单思路）、数据解析、Repository、缓存。
- UI：实验列表/详情等核心页，紧凑端与宽屏自适应。
- 网页容器：复杂交互走 `SchoolWebView`，域名与 Cookie 白名单收窄到 `phyvlab.bjtu.edu.cn`。

### 不包含

- 不做实验仿真本身的原生实现（仿真仍走网页）。
- 不做实验报告提交/预约等写操作的首版支持（先只读）。
- 不绕过平台自身登录或验证码。

## 4. 认证复用的可行路径（待内网验证）

项目已有一套可迁移的 SSO 经验：

| 环节 | 智慧教学（M5-4/M5-5） | 物理在线（预期） |
|---|---|---|
| 入口 | MIS module 28 | MIS 某个 module（调研确定） |
| 跳转 | 裸 3xx 指向明文 `thirdLogin` | 待验证（可能 HTTPS，可能明文） |
| 会话 | 落地 `Set-Cookie: JSESSIONID` | 待验证 Cookie 名与域 |
| 安全边界 | iOS/macOS 精确放行 `:88/ve/`、`:1936/kk/rp/`；Android 仅 HTTPS | 按调研结果收窄白名单，不预先放行 |

`followSmartHandshakeRedirects` 的「逐跳白名单 + 手动跟随 + 降级不扩散」模式可直接复用；物理在线若是同一厂商框架，握手形态大概率相似，但**必须以真实链路为准**，不凭类比放宽安全边界。

## 5. 平台差异

| 平台 | 策略 |
|---|---|
| Android | 仅 HTTPS；若平台强制明文，按现有红线处理并提示 |
| iOS | 若需明文，ATS 例外只加 `phyvlab.bjtu.edu.cn` 精确主机，不扩大 |
| macOS | 网页流程优先系统浏览器（沿用邮箱切片的平台差异），原生页只做只读展示 |

## 6. Apple 设计要求

- **响应**：进入平台页立即反馈加载，不卡住；网页容器有明确进度与标题。
- **反馈完整**：登录中、加载中、空数据、失败、会话过期各有状态；会话过期就地引导重新登录，不死循环。
- **空间一致**：网页容器从触发入口进入，返回沿同一路径；外部链接明确分流到系统浏览器，不把用户困在 WebView。
- **材料有层级**：网页容器顶栏用半透明材料，与内容区分，不遮挡网页可操作区域。
- **排版可伸缩**：原生列表/详情支持动态字体；网页内容不强制缩放破坏平台页面布局。

## 9. 依赖与风险

- **依赖**：现有 MIS 会话与 `followSmartHandshakeRedirects` 握手模式；`SchoolWebView` 网页容器。
- **最大风险**：当前无外网可达性，调研被阻塞 → **本里程碑在外网环境下只能完成设计，实现与验收必须等内网/VPN**。
- **框架风险**：若平台是闭源商业框架，接口可能加密或强混淆 → 以 WebView 承接复杂交互，原生只做能稳定解析的部分。
- **安全风险**：平台若强制明文 HTTP，须按现有红线单独评估，不默许放行。
