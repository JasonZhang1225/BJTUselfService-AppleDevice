## 当前网页取证（2026-08-28）

本轮通过当前 Chrome 的直接 DevTools MCP 读取已登录的北京交通大学邮件系统，只记录页面结构和请求路径，不记录邮件正文、收件人、Cookie 或会话参数。

- 页面标题为“北京交通大学邮件系统”，`body` 使用 `XT5-layout`，可判断这是 Coremail XT5 的网页端。
- 页面没有检测到 React、Vue、Angular 或全局 jQuery；主要资源是 Coremail 自有打包脚本（`X`、`M`、`316`、`986`）和 `X.technology` 样式文件，存在 webpack runtime。
- 桌面结构为：左侧功能栏 → 文件夹栏 → 邮件列表/标签页 → 阅读区；列表、阅读、回复、转发、移动、标记、删除、搜索和写信入口均存在。
- 观察到的请求路径包括 `/coremail/XT/jsp/mail.jsp`、`readMessage.jsp`、`common.jsp`、`/coremail/s/json` 和 Socket.IO 长连接。它们的请求参数和响应结构不能凭路径猜测，下一阶段要用脱敏的 DevTools 网络记录逐项确认。
- 当前 KMP 实现位于 `shared/feature/mailbox`：登录态从 MIS 会话导出 Cookie；iOS 使用 WKWebView，macOS 使用系统浏览器。现有文档已经记录学校网页在移动端是桌面多栏布局，不能直接作为手机原生体验。

## M15 目标

在不改变学校邮箱账号体系的前提下，使用 KMP 共享状态与 Compose Multiplatform 写一个原生邮件阅读前端。第一阶段先做到只读收件箱和邮件详情，验证数据协议后再做写信、回复、附件和删除等有外部影响的动作。

### 信息架构

- iPhone：文件夹列表 → 邮件列表 → 邮件详情，使用平台原生二级页面；搜索和刷新保持在当前上下文附近。
- 内置文件夹按 Coremail 的实际 FID 访问：收件箱 `1`、待办邮件 `-5`、草稿箱 `2`、已发送 `3`；已删除 `4`、垃圾邮件 `5`、病毒邮件 `6` 归入“其他文件夹”。网页树节点序号不能直接当作 FID。
- iPad/macOS：窗口足够宽时显示文件夹、列表、详情三栏；中等宽度退化为列表—详情两栏；窄窗口不强行压缩列宽。
- 邮件线程、未读状态、附件和错误状态使用明确的共享模型；正文 HTML 在受控容器中显示，外链交给系统浏览器。
- 本地默认只缓存必要的列表摘要，不把完整正文、附件或 Cookie 写入普通日志/调试快照；缓存策略需在实现前单独确认。

### Apple Design 方向

- 以系统字体、动态字号、明确的标题/发件人/日期层级构成邮件行，不依赖颜色单独表达未读。
- 交互立即反馈：按下、刷新、标记已读和切换文件夹都要有即时状态；网络等待显示在当前操作附近。
- 详情页进入和返回保持同一空间路径；加载、错误和空状态使用轻量 material surface，不用无意义的弹跳。
- macOS 补齐键盘导航、悬停反馈和可调整列宽；iPhone 保持单手可达和足够的触控命中区；减少动态效果时改用淡入淡出。

## 实施切片

1. **协议取证与适配器**：只读记录收件箱、分页、读取详情、标记已读和刷新所需请求，建立脱敏 fixture；Cookie 仍由现有内存会话边界提供。
2. **只读前端**：已新增邮箱远端适配、列表/详情状态和 Compose UI；当前覆盖收件箱、待办邮件、草稿箱、已发送、已删除、垃圾邮件和病毒邮件的文件夹切换，刷新、分页加载、已读状态、正文和附件元数据。本地正文缓存仍未实现。
3. **响应式平台布局**：已完成 iPhone/紧凑窗口列表→平台原生详情页，以及 iPad/macOS 宽窗口文件夹—列表—阅读三栏；紧凑端内嵌详情只保留“返回邮件列表”，不会与“退出邮箱功能”的顶栏返回重复；动态字体、深浅色和离线/失败状态保留在共享布局中，真实登录后的 iOS 邮箱页面仍待验收。
4. **写操作单独评审**：写信、回复、转发、删除、移动、标记和附件下载逐项确认请求、撤销/确认文案与真实账号风险；没有用户当场确认时只实现预览，不发送。

## 验收门槛

- `shared:desktopTest` 和 `shared:iosSimulatorArm64Test` 覆盖分页、日期、未读、HTML 正文安全边界及失败恢复。
- Mac 窗口验证至少覆盖窄窗口、宽窗口和调整列宽；iOS 模拟器验证列表—详情导航、返回、旋转/尺寸变化和动态字体。
- 真实账号只读验收前不执行发送、删除、移动或上传；截图与日志不得包含真实邮件正文、地址、电话、Cookie 或 URL 会话参数。最新共享层测试已通过；最终一次 Xcode Simulator 构建被用户中断，因此仍需重新构建后再做新 UI 的真实视觉验收。
- 若 Coremail 私有协议不稳定，保留现有 WebView/系统浏览器作为回退，不为了“原生化”而绕过学校权限或 TLS 安全。
