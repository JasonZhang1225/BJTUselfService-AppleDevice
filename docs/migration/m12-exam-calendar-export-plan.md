# M12：考试导出到日历（Android / iOS / macOS）目标文档

> 状态：规划中（2026-08-09 立项）。范围与验收以本文档为准；实施计划另附。
> 上游需求来源：用户 2026-08-09 提出「考试导出到日历（安卓，ios，mac）」。

## 1. 背景与现状

考试安排（M5-3）已从教务单接口严格解析考试列表，领域模型见 `shared/domain/exam/ExamSchedule.kt`：

- `examType`、`courseName`、`examTimeAndPlace`、`examStatus`、`detail`。

考试时间/地点目前以**文本**形式存在（`examTimeAndPlace`），导出前必须解析出结构化起止时间与地点。原 Android App **没有**考试导出日历功能，属于 KMP 新增能力。

## 2. 目标

让用户把考试安排一键导出到系统日历，三端体验一致且符合各平台习惯：

- 支持**导出全部**与**单条导出**。
- 导出结果落在系统日历（Android 日历、iOS/macOS 日历.app），事件含课程名、时间、地点、提醒。
- 导出动作可预测、可恢复，不静默、不重复、不污染用户日历。

## 3. 两条实现路线（需在实施前二选一或分端组合）

| 路线 | 做法 | 优点 | 风险/代价 |
|---|---|---|---|
| **A. 生成 ICS 文件** | 共享层生成 `.ics`，经文件网关/分享面板交给系统导入 | 无日历权限；三端共用生成器；用户可在导入前预览 | Android/iOS 对 ICS 的系统处理路径不同；用户需多点一步「导入」 |
| **B. 直接写系统日历** | Android `CalendarContract`、iOS/macOS `EventKit` 直接创建事件 | 一步到位；可精确控制日历、提醒、去重 | 需要运行时权限；删除/更新/去重逻辑复杂；macOS EventKit 需签名/entitlement |

**倾向**：首版以 **A（ICS）为基线**，B 作为各端增强；或按端选择——macOS 用 EventKit（保存面板/日历.app 均自然），iOS 用 EventKit 或 ICS 分享，Android 用 ICS + `Intent` 或 `CalendarContract`。最终以真实权限与系统行为调研为准，不在文档阶段锁死。

## 4. 范围

### 包含

- 共享层：`examTimeAndPlace` 文本 → 结构化 `ExamEvent`（课程名、开始/结束时间、地点、类型）的解析器；ICS 生成器（`BEGIN:VCALENDAR/VEVENT`，含 `UID`、`DTSTAMP`、`DTSTART/DTEND`、`SUMMARY`、`LOCATION`、`VALARM`）。
- 考试页 UI：列表/详情提供「导出到日历」入口；全部导出与单条导出。
- 三端导出落点：Android 分享/保存或日历 Intent；iOS `UIDocumentPicker`/分享或 EventKit；macOS `NSSavePanel` 或 EventKit。
- 权限申请流程（若走路线 B）：说明用途、仅导出时申请、拒绝后回退 ICS 文件导出。
- 提醒默认规则（如考前 1 天 + 当天），可在导出前调整。

### 不包含

- 不做日历双向同步（不从系统日历读回、不跟踪考试变更自动改日历）。
- 不做课表导出日历（另立里程碑）。
- 不做自定义日历账户/订阅源。

## 5. 平台差异

| 平台 | 导出方式 | 权限 | 备注 |
|---|---|---|---|
| Android | ICS + `Intent`/保存，或 `CalendarContract` | 写日历需运行时权限；仅导出文件不需 | 不同厂商日历 App 对 ICS Intent 支持不一 |
| iOS | ICS 分享/文件，或 EventKit | EventKit 需 `NSCalendarsUsageDescription` | ICS 经文件/分享进入「日历」导入 |
| macOS | ICS + `NSSavePanel`，或 EventKit | EventKit 需 entitlement + 使用说明 | 双击 ICS 默认日历.app 导入 |

## 6. Apple 设计要求

- **反馈完整**：导出中、成功、失败、取消各有明确状态；取消不显示红色错误（沿用文件网关既有约定）。
- **克制弹性**：导出成功反馈轻量（toast/对勾），不用弹跳动效。
- **就地说明**：权限被拒绝或导出失败时，就地给出原因与下一步（「可改为保存 .ics 文件」），不只弹系统报错。
- **排版可伸缩**：导出预览/确认中的课程名、时间、地点支持动态字体，长课程名不截断关键信息。
- **可打断**：批量导出大量考试时进度可见、可取消。

## 7. 验收

- [ ] 时间/地点解析器覆盖教务真实 `examTimeAndPlace` 全部格式（含半天、跨节次、无地点、补考/缓考等特殊文案），脱敏 fixture 测试通过。
- [ ] 生成的 ICS 三端系统日历均能正确导入（Android 日历、iOS 日历、macOS 日历.app 各真实导入一次）。
- [ ] 若走路线 B，权限申请/拒绝/授权后导出/重复导出语义正确，且拒绝后回退 ICS 文件可用。
- [ ] 单条与批量导出均验证；批量导出可取消；取消不残留半成品日历项。
- [ ] 提醒时间、时区、全天/定时事件语义正确（考试为定时事件，非全天）。
- [ ] 三端浅色/深色、窄/宽窗口通过视觉验收；导出流程不泄露账号、Cookie 到文件或日志。

## 8. 待调研（实施前必须闭环）

- [ ] 教务 `examTimeAndPlace` 的全部真实格式样本（脱敏后建 fixture）。
- [ ] 三端对 ICS 的系统处理路径与厂商差异（尤其 Android）。
- [ ] macOS EventKit 在当前 ad-hoc 签名下是否可用，还是必须 ICS。
- [ ] 时间解析失败时的降级策略（导出为全天事件 / 跳过并提示 / 保留原文本到备注）。

## 9. 依赖与风险

- **依赖**：M5-3 考试数据与缓存；M6 文件网关（若走 ICS 文件路线）。
- **风险**：时间文本格式不规则导致解析失败 → 解析器必须宽容并保留原文本兜底；直接写日历的权限/去重/删除复杂度 → 首版优先 ICS，降低对系统日历的写侵入。
